Lecture 24 Power and Size by Simulation

This is the R session for week 8. The lectures this week have been about the language of tests and about the Neyman–Pearson lemma. In this session we will see how tests perform in practice. The R technique we will use here is the indicator average from lecture 12, where the indicator now marks the samples for which the test rejects. The written reference for this is in appendix B.

24.1 The Size of a Test by Simulation

The test we consider today is the one-sided zz-test from example 22.6, in the numerical setting of the example: we have n=25n=25 observations from N⁢(θ,σ2)N(\theta,\sigma^{2}) with known σ=2\sigma=2 and we want to test H0:θ=10H_{0}\colon\theta=10 against H1:θ>10H_{1}\colon\theta>10 at level α=0.05\alpha=0.05, i.e. we reject if and only if X¯>10.658\bar{X}>10.658. By definition 22.4, the power function β⁢(θ)=ℙθ⁢(X¯>10.658)\beta(\theta)=\mathbb{P}_{\theta}(\bar{X}>10.658) is a probability, and by proposition A.14 we can approximate this probability by the proportion of samples where the test rejects. As in lecture 12, we write a function which, for one run of the test, returns TRUE if the test rejects and FALSE otherwise. The command mean can then be used to get the proportion of rejections. Before you run the code, predict the value it prints. Will it be exactly 0.050.05? How far away from 0.050.05 would it have to be before you would suspect a mistake in the code?

n <- 25
sigma <- 2
theta0 <- 10
crit <- theta0 + qnorm(0.95) * sigma / sqrt(n)
z_reject <- function(theta) {
x <- rnorm(n, mean = theta, sd = sigma)
mean(x) > crit
}
set.seed(2026)
mean(replicate(10000, z_reject(theta0)))
## [1] 0.0523

The rejection rate under H0H_{0} is 0.05230.0523. This is the estimated size of the test in the sense of definition 22.5. The value is not exactly 0.050.05, and it should not be: as in lecture 12, the estimate has standard deviation 0.05⋅0.95/10000=0.0022\sqrt{0.05\cdot 0.95/10000}=0.0022. Thus, a value between 0.0460.046 and 0.0540.054 is what we expect for a correct test, while a value of 0.070.07 would point to an error in the code. Calling the same function with a value of θ\theta above θ0\theta_{0} gives the power at this point; for θ=10.5\theta=10.5 and θ=11\theta=11 the exact values are 0.3460.346 and 0.8040.804, from example 22.6.

24.2 The Power Curve

A single number is a poor summary of a test, so we now consider the power function over a grid of alternatives. Figure 24.1 shows the rejection rates on the grid of values from 99 to 1212 in steps of 0.10.1 for three level 0.050.05 tests: the one-sided zz-test from above, the two-sided zz-test from example 22.7 and the one-sided zz-test applied to the first 1212 observations only. The last test is wasteful, but it is a legal level 0.050.05 test. The script R/S24-power.R can be used to reproduce the figure. Before you look at the figure, predict how the two-sided test compares with the one-sided test. Is its rejection rate above or below that of the one-sided test for θ<10\theta<10? Is it above or below for θ>10\theta>10?

The line in the figure is the exact power function (22.1) of the one-sided test, and the filled circles lie on it. All three curves pass through 0.050.05 at θ0=10\theta_{0}=10, as required for level 0.050.05 tests, and the tests differ only in power. The two-sided test has lower power than the one-sided test for θ>10\theta>10 and much higher power for θ<10\theta<10. Thus, neither curve lies above the other everywhere, and this illustrates proposition 23.5. From example 23.3 and proposition 23.4 we know that no level 0.050.05 test based on these 2525 observations can reject at θ=11\theta=11 more than 80%80\% of the time. The crosses show the cost of having discarded thirteen of the observations: the power at θ=11\theta=11 decreases from 0.800.80 to 0.530.53.

24.3 Looking at the Data More Than Once

The recipe of the first section gives the size of every procedure which ends in a decision, and we now apply it to a procedure whose size is not what it seems to be. Assume that the observations arrive one at a time, up to 100100 in total, and that we perform the two-sided zz-test from example 22.7 after every ten observations. We stop and reject H0H_{0} as soon as one of the pp-values is below 0.050.05: this is the case of the researcher who “collects a few more data points and looks again”. The following function simulates one run of this procedure under H0H_{0}, using the pp-value 2⁢(1−Φ⁢(|z|))=2⁢Φ⁢(−|z|)2\bigl{(}1-\Phi(|z|)\bigr{)}=2\,\Phi(-|z|) from lecture 22, and returns TRUE if the procedure rejects. Before you run the code, predict the rejection rate. Each of the ten tests has level 0.050.05. Will the rejection rate be 0.050.05? Could it be as large as 0.50.5?

peek <- function() {
x <- rnorm(100, mean = theta0, sd = sigma)
for (k in seq(10, 100, by = 10)) {
z <- sqrt(k) * (mean(x[1:k]) - theta0) / sigma
if (2 * pnorm(-abs(z)) < 0.05) return(TRUE)
}
FALSE
}
set.seed(2026)
mean(replicate(10000, peek()))
## [1] 0.1993

The procedure rejects a true null hypothesis in 20%20\% of all runs, four times as often as the level of the single tests suggests. By lemma 22.9, each of the ten pp-values is uniformly distributed under H0H_{0}, and thus each single look rejects with probability 0.050.05. The procedure, however, rejects if at least one of the ten looks rejects. Since the probability of a union is at most the sum of the probabilities, the rejection rate cannot exceed 10⋅0.05=0.510\cdot 0.05=0.5, and ten independent tests would give 1−0.9510=0.401-0.95^{10}=0.40. Here the looks share observations: a sample which is far from rejection at one look is likely to be far from rejection at the next look as well, and for this reason the rate 0.200.20 is smaller than both values. The level is a property of the whole procedure, including the rule which determines when to stop, and for this reason the sample size must be fixed before the data are seen.
